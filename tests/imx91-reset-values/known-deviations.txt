# KNOWN RESET-VALUE DEVIATIONS -- i.MX 91
#
# THIS NUMBER MUST GO DOWN.  It is a TO-DO LIST, not a certificate.
#
#     "An independent whitelist doesn't merely MISS the bug -- IT CERTIFIES IT."
#                                                        -- ollama_95_neutron
#
# The gate fights this file in BOTH directions: a mismatch that is NOT here FAILS
# (a new lie), and an entry here that now MATCHES the RM also FAILS ("this is
# fixed -- delete the line").  An allowlist that never shrinks stops being a
# to-do list and becomes a CERTIFICATE.
#
# THREE KINDS OF ENTRY, and the distinction is the whole point:
#
#   DECISION   -- a deliberate deviation WITH ITS REASON.  The RM's reset column is
#                 the COLD-POR value; we boot -kernel and skip the ROM and TF-A, so
#                 some registers must be synthesised or the guest breaks.
#                 "A deviation with a reason is a decision; a deviation without one
#                  is a bug you have agreed not to look at."   -- rt1180emulator
#
#   UNMODELLED -- the BLOCK is a stub or the catch-all.  It reads 0 and swallows
#                 writes.  This is an ABSENT model, not a lying one -- a different
#                 fact, and conflating the two buries the real bugs.
#
#   UNTRIAGED  -- a REAL DEVICE MODEL returning a value the silicon would never
#                 produce.  THIS is the bug list.
#
# ON CAPABILITY REGISTERS (PARAM, HW_FEATURE, FIFO depth, channel counts):
#     UNDER-reporting is the SAFE error direction -- the guest uses fewer features,
#     all of which we implement.  OVER-reporting is the dangerous one: it is a
#     promise the emulator makes on the chip's behalf, it WORKS HERE, and it FAILS
#     ON HARDWARE.  The TPM advertised 6 PWM channels where silicon has 4.
#
# format: <instance> <register> <kind>[: reason]
#
